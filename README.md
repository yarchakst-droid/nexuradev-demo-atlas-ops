# Atlas Ops — диспетчерська панель

Робочий demo-проєкт для портфоліо: внутрішня диспетчерська панель логістичної компанії. 3 екрани, реальні API-роути (статус відправлення можна оновити, і це реально зберігається на сервері), справжні фото водіїв з Unsplash, власна SVG-карта маршруту.

Свідомо інший підхід до дизайну, ніж у інших проєктів портфоліо: внутрішні дашборди в реальному житті стримані й функціональні. Темна тема, колір лише для статусної семантики, мінімум декоративних анімацій, без tilt/glow/3D-ефектів.

## Стек

- **Next.js 16** (App Router, Turbopack) + **TypeScript**
- **Tailwind CSS 4** (CSS-first `@theme` — токени в `src/app/globals.css`, без `tailwind.config.ts`)
- **Framer Motion** — лише функціональні анімації: лічильники KPI, що рахують до цільового числа при завантаженні, і SVG stroke-animation "малювання" маршруту на карті. Без важких 3D-бібліотек.
- Реальні фото водіїв — Unsplash-портрети, усі посилання перевірені `curl -I` і візуально перед вбудовуванням
- Реальний бекенд — Next.js Route Handlers з in-memory сховищем (без БД, як і в проєктах 2–3)

## Екрани

| Маршрут | Що там |
|---|---|
| `/` | Дашборд відправлень: KPI-смуга (5 лічильників з count-up анімацією), фільтр за статусом, таблиця з 9 відправлень (маршрут, водій, ETA, прогрес-бар, семантичний колір статусу) |
| `/shipments/[id]` | Деталі маршруту: власна SVG-схема карти з анімованою пунктирною лінією маршруту (`pathLength` 0→1 при завантаженні), точка поточного положення на маршруті, хронологія рейсу, кнопки дії диспетчера |
| `/drivers` | Список водіїв: картки з реальними фото, статус доступності (на маршруті / доступний / не на зміні), транспорт, номерний знак, контакти, посилання на поточний або останній рейс |

## Чому це "робочий" проєкт, а не просто фронтенд

- `POST /api/shipments/[id]/status` — диспетчер реально змінює статус відправлення (вчасно / затримка / критично / доставлено) кнопками на сторінці маршруту. Запит валідується на сервері (невідомий статус → 400, невідоме відправлення → 404), прогрес і хронологія перераховуються на бекенді, а не в компоненті.
- `GET /api/shipments` — таблиця й KPI-смуга отримують дані одним реальним запитом, з `?status=` фільтром на сервері та приєднаним водієм (join) для кожного відправлення.
- `GET /api/drivers` — список водіїв із приєднаним поточним/останнім рейсом.

Спробуйте: відкрийте будь-яке відправлення, натисніть "Позначити доставленим" — і поверніться на дашборд: KPI "Доставлено сьогодні" і статус у таблиці відображають щойно збережені на сервері дані.

**Немає БД (це demo)** — стан живе в `globalThis` у пам'яті Node-процесу (`src/lib/store.ts`) і скидається при рестарті сервера, як і в Mentora (проєкт 3).

## Ключові компоненти

```
src/
├── data/
│   ├── shipments.ts                   # 9 відправлень: маршрут, вантаж, геометрія карти, хронологія
│   └── drivers.ts                     # 11 водіїв, реальні Unsplash-портрети
├── lib/
│   ├── types.ts                       # Shipment, Driver, RouteGeometry, TimelineEvent
│   ├── store.ts                       # in-memory статус відправлень (globalThis, як і в Mentora)
│   ├── shipments.ts / drivers.ts      # читання + join водій↔відправлення
│   └── stats.ts                       # обчислення KPI з масиву відправлень
├── app/api/
│   ├── shipments/route.ts             # GET, фільтр за статусом, join водія
│   ├── shipments/[id]/status/route.ts # POST, реальна валідація + перерахунок прогресу
│   └── drivers/route.ts               # GET, join поточного рейсу
├── components/
│   ├── dashboard/CountUp.tsx          # framer-motion animate() від 0 до цільового числа
│   ├── dashboard/KpiStrip.tsx         # 5 KPI-плиток з моношрифтом для чисел
│   ├── dashboard/ShipmentsTable.tsx   # таблиця з кольоровим кодуванням статусу
│   ├── route/RouteMap.tsx             # власна схематична SVG-карта, motion.path pathLength-анімація,
│   │                                     позиція вантажівки обчислюється через getPointAtLength()
│   ├── route/StatusActionBar.tsx      # кнопки диспетчера, реальний POST на зміну статусу
│   └── drivers/DriverCard.tsx         # картка водія з фото, статусом і посиланням на рейс
```

## Запуск локально

### Одна команда з кореня репозиторію
```bash
npm run prot:atlas
```
Підніме сайт на `http://localhost:3212`.

Або разом з іншими demo-проєктами:
```bash
npm run prot
```

### Вручну
```bash
cd portfolio-demos/04-atlas-ops-dispatch
npm install
npm run dev
```

### Продакшн-білд
```bash
npm run build
npm run start
```

Публічний деплой не обов'язковий — внутрішні тули зазвичай не публікують. Формат здачі — чисті екрани для скріншотів/відео.

## Технічні нотатки

- **Карта — не фото, а власна SVG-схема**: замість реального растрового знімка карти (ліцензійні ризики, невідповідність маршруту) — мінімалістична сітка + дві "плями" рельєфу + анімована пунктирна крива між пінами. Дає повний контроль над точкою маршруту й уникає залежності від зовнішнього map-провайдера в demo-проєкті.
- **Позиція вантажівки на маршруті**: прихований (`stroke: none`) вимірювальний `<path>` з тією ж геометрією, що й видимий маршрут; `getTotalLength()` + `getPointAtLength()` обчислюють точку за `progressPercent` — стандартний SVG-прийом без сторонніх бібліотек.
- **`globalThis`-сховище**: як і в Mentora, прив'язане до `globalThis`, а не до модуля — інакше Next.js dev-сервер скидав би статуси відправлень після кожного hot-reload.
- **Шрифти**: `Inter` (інтерфейс) + `JetBrains Mono` (коди відправлень, номери, відсотки, дати) — моноширинні цифри навмисно підкреслюють "дата-інструмент", на відміну від редакційних серифів у Mentora й Loom.

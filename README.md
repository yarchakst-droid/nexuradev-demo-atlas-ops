# Atlas Ops — диспетчерська панель

Робочий demo-проєкт для портфоліо: внутрішня диспетчерська панель логістичної компанії. Дашборд з фінансовими графіками, водії й автопарк з можливістю додавання, трекер на карті, месенджер з водіями, заплановані поїздки з призначенням водія, оплата рахунків, звіти. Реальні API-роути (статуси, повідомлення, рахунки — усе справді зберігається на сервері під час сесії), справжні фото водіїв з Unsplash, власна SVG-карта маршрутів.

Дизайн навмисно стриманий, у стилі Apple: плоскі поверхні, жодного градієнта, колір лише для статусної семантики, мінімум декоративних анімацій.

## Демо-доступ

Сайт захищений входом — на `/login` логін і пароль уже підставлені у форму. Це єдиний акаунт, і він навмисно **лише для перегляду**: весь функціонал відкритий і клікабельний, але дії, що змінюють спільні демо-дані (додати водія/авто, надіслати повідомлення, запланувати чи призначити рейс, позначити рахунок оплаченим), повертають чесну відповідь "це демо-акаунт лише для перегляду" замість мовчазного success. Оновлення статусу відправлення чи техобслуговування авто лишаються реально робочими для всіх — це і є "доказ" реального бекенду, і skip'ати їх шкоди не завдає.

## Стек

- **Next.js 16** (App Router, Turbopack, `proxy.ts` для гейту авторизації) + **TypeScript**
- **Tailwind CSS 4** (CSS-first `@theme` — токени в `src/app/globals.css`, без `tailwind.config.ts`)
- **Framer Motion** — лише функціональні анімації: лічильники KPI, SVG stroke-animation маршруту. Без важких 3D-бібліотек
- Реальні фото водіїв — Unsplash-портрети; новододані водії отримують аватар-заглушку з ініціалами (`components/shared/Avatar.tsx`)
- Реальний бекенд — Next.js Route Handlers з in-memory сховищем (без БД, як і в проєктах 2–3), сесія через httpOnly-cookie

## Екрани

| Маршрут | Що там |
|---|---|
| `/login` | Вхід у систему з підставленими демо-даними |
| `/` | Дашборд: KPI-смуга з живою дельтою між опитуваннями, блок «Фінанси та автопарк» (дохід за 30 днів з графіком, середній чек, завантаженість автопарку), таблиця відправлень з фільтром за статусом |
| `/shipments/[id]` | Деталі маршруту: SVG-схема з анімованою лінією, хронологія рейсу, кнопки зміни статусу |
| `/drivers`, `/drivers/[id]` | Список і картка водія: історія рейсів, закріплений транспорт, кнопка написати в месенджер, форма додавання нового водія |
| `/fleet`, `/fleet/[id]` | Автопарк: стан, пробіг, паливо, перемикання на обслуговування, форма додавання авто |
| `/scheduled` | Заплановані поїздки: призначення водія й транспорту на майбутній рейс, створення нової поїздки |
| `/tracker` | Трекер на карті: усі активні відправлення на одній SVG-схемі мережі, живі позиції вантажівок |
| `/messenger` | Переписка диспетчера з водіями по поточних рейсах |
| `/billing` | Рахунки клієнтів, статус оплати, позначення оплаченим |
| `/reports` | Зведена статистика по відправленнях, водіях, автопарку |

## Чому це "робочий" проєкт, а не просто фронтенд

- `POST /api/shipments/[id]/status`, `POST /api/vehicles/[id]/status` — реально змінюють дані на сервері, з валідацією.
- `GET /api/search` — перехресний пошук по відправленнях/водіях/автопарку одразу трьома мовами, живить командну палітру в топбарі (⌘K).
- `GET /api/alerts` — сповіщення обчислюються з поточного стану складу (критичні/затримані відправлення, низький рівень пального, авто на плановому ТО), а не є статичним текстом.
- `GET /api/finance`, `GET /api/billing` — фінансова статистика й рахунки рахуються з реальних даних відправлень (`revenue`, `client` на кожному відправленні).
- `POST /api/drivers`, `POST /api/vehicles`, `POST /api/messages`, `POST /api/scheduled`, `POST /api/scheduled/[id]/assign`, `POST /api/billing/[id]/pay` — повністю валідовані запити, які в реальному кабінеті зберігали б дані; у цьому демо вони гейтяться `lib/demo-guard.ts` і повертають 403 з поясненням.

**Немає БД (це demo)** — стан живе в `globalThis` у пам'яті Node-процесу (`src/lib/store.ts`) і скидається при рестарті сервера.

## Запуск локально

### Одна команда з кореня репозиторію
```bash
npm run prot:atlas
```
Підніме сайт на `http://localhost:3212`.

### Вручну
```bash
cd portfolio-demos/04-atlas-ops-dispatch
npm install
npm run dev
```

### Продакшн-білд
```bash
npm run build
npm run start
```

## Технічні нотатки

- **Авторизація** — `src/proxy.ts` (Next 16 перейменував `middleware.ts` у `proxy.ts`) перевіряє httpOnly-cookie й редіректить на `/login`, якщо її немає. Єдиний акаунт навмисно відкритий — це публічне демо, а не продукт.
- **Read-only гейт** — окремий від авторизації: `lib/demo-guard.ts` блокує лише дії, що додають/змінюють спільні дані, лишаючи статус-тогли живими для всіх відвідувачів.
- **Карта — не фото, а власна SVG-схема**: мінімалістична сітка + анімована пунктирна крива між пінами. Трекер (`/tracker`) переносить цей самий підхід на всю мережу одразу — координати міст узгоджені між усіма відправленнями (`data/shipments.ts`), тож маршрути коректно лягають на спільну схему.
- **Позиція вантажівки на маршруті**: прихований (`stroke: none`) вимірювальний `<path>` + `getTotalLength()`/`getPointAtLength()`. На трекері вимірювання відбувається через ref-callback (а не `useEffect`), щоб коректно переміряти позицію щоразу, коли `progressPercent` змінюється після опитування.
- **`globalThis`-сховище**: прив'язане до `globalThis`, а не до модуля — інакше Next.js dev-сервер скидав би дані після кожного hot-reload.
- **Шрифти**: `Inter` (інтерфейс) + `JetBrains Mono` (коди, номери, суми, дати).
